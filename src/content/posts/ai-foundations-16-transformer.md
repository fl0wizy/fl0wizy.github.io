## 1. 기억을 계속 넘기는 대신, 필요한 정보를 직접 찾아보면 어떨까

앞 장: [순환 신경망 - 13장](/post/ai-foundations-15-rnn)

13장에서 RNN은 이전 상태를 다음 시점에 넘겼고, LSTM과 GRU는 그중 무엇을 남기고 무엇을 새로 쓸지 조절했다. 하지만 긴 문장의 앞부분에 있는 정보를 뒤에서 쓰려면 여전히 여러 번의 상태 갱신을 거쳐야 했다. 단순 인코더-디코더에서는 입력 전체를 마지막 상태 하나로 요약하는 부담도 있었다.

번역을 한다고 생각해 보자. 문장을 한 번 읽고 원문을 덮은 채 기억에만 의존하기보다, 다음 단어를 만들 때 원문의 필요한 부분을 다시 볼 수 있으면 좋다. **어텐션(attention)은 현재 계산에 필요한 정보를 얼마나 참고할지 점수를 매기고, 그 비율에 따라 정보를 모으는 연산**이다.

어텐션은 Transformer와 같은 말이 아니다. RNN 기반 번역 모델에도 어텐션을 붙일 수 있다. 2014년에 공개되고 ICLR 2015에 발표된 [Bahdanau 등의 연구](https://arxiv.org/abs/1409.0473)는 입력을 고정 길이 벡터 하나에 압축하는 병목을 줄이기 위해 필요한 입력 부분을 참고하게 했다. 이후 2017년 Transformer는 RNN 없이 어텐션을 중심으로 시퀀스를 처리하도록 구조를 바꿨다.

따라서 이 장의 위치는 **가중치를 학습하는 새로운 원리**가 아니라 **입력들 사이에서 정보를 전달하는 새로운 구조**다. 가중합, 활성화 함수, Softmax, 손실, 역전파는 앞 장의 부품을 다시 사용한다. 먼저 전체 건물을 보고, 각 부품을 열어 본 다음, 마지막에 문장 하나가 실제로 통과하는 과정을 연결하겠다.

## 2. Transformer 전체 구조에서 지금 보고 있는 위치 잡기

![어텐션과 Transformer 구조 - 14장 — 1번 그림](/images/ai-study/8db803e6f5663eea24c6.png)

그림 왼쪽이 **인코더**, 오른쪽이 **디코더**다. 인코더는 입력 문장의 각 위치를 주변 문맥이 반영된 벡터로 바꾼다. 디코더는 지금까지 생성한 출력과 인코더가 만든 표현을 참고해 다음 토큰을 예측한다. 그림 아래에서 위로 데이터가 흐르고, num\_layers는 같은 종류의 블록을 여러 층 쌓는다는 뜻이다.

처음에는 다섯 군데만 구분하면 된다.

| 위치 | 하는 일 | 앞 장과의 연결 |
| --- | --- | --- |
| 토큰화와 임베딩 | 글을 모델이 계산할 숫자 벡터로 바꿈 | 입력을 숫자로 표현하는 전처리와 학습된 표현 |
| 위치 정보 | 벡터에 순서 단서 제공 | RNN이 처리 순서로 갖던 정보를 별도로 제공 |
| 어텐션 | 다른 위치에서 필요한 정보를 가져와 섞음 | 가중합이지만 혼합 비율을 현재 입력에서 계산 |
| FFN, Add, Norm | 각 위치의 표현 변형과 안정적인 학습 | Dense·활성화·계산 그래프·역전파 |
| Linear와 Softmax | 어휘의 각 후보 점수와 확률 생성 | 2장의 다중 분류와 11장의 손실 학습 |

이 구조가 모든 언어 모델에 그대로 들어가는 것은 아니다. BERT는 주로 왼쪽 인코더 형태를, GPT는 인코더를 따로 두지 않는 디코더 기반 형태를, T5는 인코더와 디코더 둘 다 사용한다. 이 차이는 각각의 블록을 이해한 뒤 다시 살펴보자.

## 3. 토큰 번호와 임베딩 벡터는 무엇이 다른가

컴퓨터는 문장 자체에 행렬곱을 할 수 없다. 먼저 텍스트를 **토큰**이라는 처리 단위로 나누고 토큰마다 정수 ID를 붙인다. 토큰은 단어 전체일 수도 있고 단어의 일부, 기호일 수도 있다. 설명을 쉽게 하기 위해 여기서는 “I like movies”를 세 토큰처럼 다룬다. 실제 분할은 토크나이저마다 달라질 수 있다.

예를 들어 “I love you”가 \[101, 1567, 1128\]로 변환되었다고 가정할 수 있다. 이 숫자는 설명용 예이지 특정 실제 토크나이저의 결과라고 정한 것이 아니다. ID 1567이 101보다 의미가 15배 크다는 뜻도 아니다. ID는 단어 사전의 항목을 찾는 번호다.

**임베딩(embedding)**은 그 번호를 학습 가능한 숫자 벡터로 바꾸는 과정이다. 어휘 수가 V이고 표현 크기가 d\_model이면 임베딩 표는 V × d\_model 크기다. 토큰 ID에 해당하는 행을 읽어 그 토큰의 초기 벡터로 사용한다. 임베딩 표 역시 손실과 역전파를 통해 학습되는 매개변수다.

![어텐션과 Transformer 구조 - 14장 — 2번 그림](/images/ai-study/3b656bbe274b8fbf042e.png)

위 예에서는 세 토큰의 표현을 각각 네 숫자로 나타냈으므로 X는 3 × 4이다. 첫 번째 축은 토큰 위치, 두 번째 축은 표현의 성분이다. 성분 하나하나가 반드시 “긍정 정도”, “주어 정도”처럼 사람이 정한 뜻을 가지는 것은 아니다. 여러 성분의 조합으로 유용한 표현을 학습한다.

어텐션을 거치기 전의 같은 토큰 임베딩은 같은 표에서 가져올 수 있다. 어텐션을 거친 뒤에는 주변 문장에 따라 표현이 달라진다. “은행에 돈을 맡겼다”의 은행과 다른 문맥의 은행을 구분할 단서를 만드는 과정이라고 생각하면 된다.

## 4. Self-Attention은 같은 입력 안에서 서로 참고하는 계산이다

![어텐션과 Transformer 구조 - 14장 — 3번 그림](/images/ai-study/340d6398151f67bebfd4.png)

**Self-Attention**의 self는 각 토큰이 자기 자신만 본다는 뜻이 아니다. 질문하는 쪽과 참고할 정보가 **같은 시퀀스에서 만들어진다**는 뜻이다. 문장의 각 토큰은 자신을 포함한 다른 토큰들의 정보를 모아 자기 표현을 갱신한다. 단, 실제로 볼 수 있는 위치는 마스크에 따라 제한될 수 있다.

입력 관계를 매번 새로 계산하므로 “동적 연결”이라고 부를 수 있다. CNN의 필터가 가까운 고정 영역을 보고, RNN이 이전 상태를 통해 정보를 받았다면, 어텐션은 허용된 범위 안에서 멀리 떨어진 위치도 직접 참고한다. 이 직접 참조가 거리에 따른 긴 전달 경로를 줄인다.

거리 자체가 무의미해지거나 위치가 사라져야 한다는 뜻은 아니다. 어떤 위치에 있는 정보인지도 중요하므로 위치 정보를 따로 제공한다. 또한 모든 문맥을 완벽하게 기억하게 되는 것은 아니다. 입력 길이 제한, 계산량, 학습 데이터, 여러 정보의 경쟁 같은 문제가 남는다.

## 5. Q·K·V는 같은 입력을 세 가지 역할로 바꾼 것이다

다른 토큰을 참고하려면 두 가지가 필요하다. 먼저 누구의 정보를 가져올지 판단하고, 다음으로 그곳에서 실제 내용을 가져와야 한다. 이 역할을 나누는 것이 Query, Key, Value다.

| 기호 | 쉬운 역할 설명 | 비유의 한계 |
| --- | --- | --- |
| Q, Query | 현재 위치가 어떤 정보를 찾을지 나타내는 벡터 | 사람이 쓴 검색어 자체는 아님 |
| K, Key | 각 위치가 어떤 정보와 관련 있는지 비교할 벡터 | DB의 고유 키나 비밀번호가 아님 |
| V, Value | 해당 위치에서 실제로 가져와 섞을 내용 벡터 | 정답 라벨이 아님 |

![어텐션과 Transformer 구조 - 14장 — 4번 그림](/images/ai-study/36b553acdbe88f24cac5.png)

같은 입력 X에 서로 다른 가중치 행렬 W\_Q, W\_K, W\_V를 곱해 Q, K, V를 만든다. 선형 변환이란 입력 성분에 가중치를 곱해 더하여 새로운 성분을 만드는 계산이다. 아래는 편향을 생략한 표기다.

![어텐션과 Transformer 구조 - 14장 — 5번 그림](/images/ai-study/29cdb1670351c58cde37.png)

X가 n × d\_model이고 W\_Q와 W\_K가 d\_model × d\_k이면 Q와 K는 n × d\_k이다. W\_V가 d\_model × d\_v이면 V는 n × d\_v이다. n은 토큰 수, d\_k는 query·key 크기, d\_v는 value 크기다. Q와 K의 성분 수는 내적으로 비교할 수 있게 같아야 한다.

처음의 가중치는 임의의 작은 값 등으로 초기화하고, 다음 토큰 예측 같은 학습 목표의 손실로 조정한다. 학습이 끝난 추론에서는 보통 W들은 고정되어 있고, 입력이 달라질 때 Q·K·V가 새로 계산된다. **W는 학습 매개변수이고 Q·K·V는 입력에 따른 계산 결과**다.

그림의 생략점은 일부 성분을 생략했다는 뜻이다. 보이는 숫자 몇 개만 곱해서 뒤의 전체 내적을 재현할 수 있는 완전한 행렬 예제는 아니다. 실제 계산은 생략된 모든 성분을 포함한다.

## 6. 첫 단계: Q와 K의 내적으로 관련도 점수를 만든다

![어텐션과 Transformer 구조 - 14장 — 6번 그림](/images/ai-study/e1386e9ff90a3a4e1adb.png)

한 query qᵢ와 한 key kⱼ의 내적은 같은 성분끼리 곱해 더한 값이다. 모든 조합을 한꺼번에 계산하려면 Q와 K의 전치 Kᵀ를 곱한다. Q가 n × d\_k, Kᵀ가 d\_k × n이므로 결과는 n × n이다.

결과 행렬의 **행 i는 정보를 받는 위치**, **열 j는 참고할 위치**다. 예를 들어 “like” 행의 “movies” 열은 like 위치가 movies에서 정보를 가져올 때의 점수다. 학습된 Q와 K가 서로 다른 변환에서 나오므로 이 점수는 반대 방향과 꼭 같지 않다. 즉 i가 j를 참고하는 정도와 j가 i를 참고하는 정도는 다를 수 있다.

이 점수를 유사도라고 부르기도 하지만, 정규화된 코사인 유사도나 사람이 판단한 의미 유사도와 완전히 같은 것은 아니다. **학습 목표에 맞게 정보를 섞기 위해 만들어진 호환성 점수**라고 이해하는 편이 정확하다.

## 7. 둘째 단계: 왜 제곱근으로 나누는가

![어텐션과 Transformer 구조 - 14장 — 7번 그림](/images/ai-study/eb6a441d75e9236697f3.png)

QKᵀ의 각 값을 √d\_k로 나눈다. key가 64차원이면 √64=8로 나눈다. 여기서 d\_k는 **한 헤드의 query·key 차원**이다. 전체 임베딩 차원 d\_model과 언제나 같은 값은 아니다. d\_model=512, 헤드 8개의 전형적인 예에서는 d\_k=64다.

차원이 커지면 내적에 더하는 항이 많아져 점수의 변동도 커질 수 있다. 성분들이 독립적이고 평균 0, 분산 1이라고 단순화하면 내적의 분산은 d\_k에 비례한다. √d\_k로 나누면 점수 규모를 조절할 수 있다. 이것이 scaled, 즉 크기를 조정했다는 뜻이다.

점수가 너무 벌어지면 Softmax가 한 위치에 거의 1, 나머지에 거의 0을 줄 수 있다. 이런 극단적인 구간에서는 학습에 필요한 변화 신호가 작아질 수 있다. 스케일링은 이를 완화하려는 장치이지, 어떤 상황에서도 기울기가 안정적이라는 보장은 아니다.

## 8. 셋째 단계: Softmax로 한 행의 참고 비율을 만든다

Softmax는 점수들을 0과 1 사이의 값으로 바꾸고, 합이 1이 되게 한다. 2장에서 클래스 확률을 만들 때 썼던 같은 함수다. 여기서는 클래스가 아니라 **참고할 토큰 위치**를 대상으로 적용한다.

![어텐션과 Transformer 구조 - 14장 — 8번 그림](/images/ai-study/d3bcd50e7ef9a5d57357.png)

한 행의 큰 점수에는 큰 비율이, 작은 점수에는 작은 비율이 배정된다. 각 행을 독립적으로 계산하므로 모든 행의 합은 각각 1이다. 열의 합이 1일 필요는 없다. 안정적인 구현에서는 각 행의 최댓값을 뺀 뒤 지수 함수를 적용한다. 모든 점수에서 같은 값을 빼도 비율은 같고, 지나치게 큰 지수 계산을 피할 수 있다.

앞의 QKᵀ 값이 첫 행 (110, 90, 80), 둘째 행 (70, 99, 70), 셋째 행 (90, 70, 100)이고 d\_k=64라고 하자. 8로 나눈 뒤 각 행에 Softmax를 적용하면 다음과 같다.

![어텐션과 Transformer 구조 - 14장 — 9번 그림](/images/ai-study/4f3e74134863fc73b183.png)

첫 행의 약 0.9045는 I 위치가 I의 value를 약 90.45% 비중으로 섞는다는 뜻이다. like 위치의 약 0.9494는 like가 자기 위치에 큰 비중을 두는 예다. 세 번째 행은 I에서 약 21.87%, like에서 약 1.80%, movies에서 약 76.33%를 가져온다. 숫자는 표시 자리에서 반올림했다.

이 예가 실제 언어에서 항상 자기 자신을 많이 본다는 법칙은 아니다. 설명용 점수가 이런 결과를 만든 것이다. **어텐션 가중치 A는 입력마다 계산되는 혼합 비율**이고, W\_Q처럼 학습 후 저장된 매개변수 자체가 아니다. “가중치”라는 같은 말을 쓰지만 역할이 다르다.

## 9. 넷째 단계: 그 비율로 V를 섞어 새로운 표현을 만든다

어디를 참고할지 정했다면 실제 내용을 모아야 한다. 어텐션 비율 A와 value 행렬 V를 곱한다. A는 n × n, V는 n × d\_v이므로 결과 Z는 n × d\_v이다. 토큰마다 새로운 내용 벡터 하나가 만들어진다.

![어텐션과 Transformer 구조 - 14장 — 10번 그림](/images/ai-study/eb402163462613b8c8f9.png)

예를 들어 첫 번째 토큰의 새 표현은 0.9045v₁ + 0.0742v₂ + 0.0213v₃ 정도의 가중합이다. v₁·v₂·v₃는 벡터이므로 성분별로 이 계산을 한다. 출력이 “참고한 단어의 이름” 하나가 아니라 **여러 위치의 정보가 섞인 새 벡터**라는 점이 중요하다.

왜 K와 V를 따로 만들었는지도 이제 보인다. K는 누구의 정보를 참고할지 비교하는 데 쓰고, V는 실제 내용을 전달하는 데 쓴다. 같은 입력에서 나오더라도 선택 기준과 전달 내용을 별도로 학습할 여지를 준다.

네 단계를 한 식으로 모은 것이 scaled dot-product attention이다.

![어텐션과 Transformer 구조 - 14장 — 11번 그림](/images/ai-study/c8c08a3a1c82148c43dd.png)

Q·K·V 만들기, 내적, 크기 조정, Softmax, V의 가중합까지가 하나의 어텐션 계산이다. 전체 문장의 각 위치에 문맥이 반영된 표현을 만드는 과정이며, 이것만으로 완성된 Transformer 전체가 되는 것은 아니다.

## 10. 작은 코드로 계산 순서와 행렬 크기를 확인하기

아래 코드는 학습된 언어 모델이 아니라 어텐션 계산을 확인하기 위한 작은 수치 예제다. Q·K·V를 직접 주어 네 단계 중 점수 계산부터 출력까지 확인한다. 실제 모델에서는 앞서 본 X와 W의 행렬곱으로 이 값들을 만든다.

```py
import numpy as np

def softmax_rows(scores):
    shifted = scores - scores.max(axis=-1, keepdims=True)
    values = np.exp(shifted)
    return values / values.sum(axis=-1, keepdims=True)

def attention(Q, K, V, causal=False):
    scores = Q @ K.T / np.sqrt(Q.shape[-1])
    if causal:
        blocked = np.triu(np.ones(scores.shape, dtype=bool), k=1)
        scores = np.where(blocked, -np.inf, scores)
    weights = softmax_rows(scores)
    return weights @ V, weights

Q = np.array([[1., 0.], [0., 1.], [1., 1.]])
K = np.array([[1., 0.], [0., 1.], [1., 1.]])
V = np.array([[10., 0.], [0., 10.], [5., 5.]])

Z, weights = attention(Q, K, V)
print(weights.shape)      # (3, 3)
print(Z.shape)            # (3, 2)
print(weights.sum(axis=-1))  # [1., 1., 1.]
```

Q와 K가 이 예에서는 우연히 같은 값이지만, 일반적으로는 서로 다른 학습 변환을 사용한다. causal 옵션은 뒤에서 설명할 미래 위치 가림이다. 이 코드는 같은 길이의 단일 시퀀스만 다루며 배치·여러 헤드·패딩 처리를 모두 구현한 것은 아니다.

## 11. 한 가지 참고 방식으로 부족해서 여러 헤드를 사용한다

문장에는 주어와 동사의 관계, 지시어가 가리키는 대상, 가까운 표현의 결합 등 여러 종류의 관계가 있다. 하나의 혼합 방식만 사용하는 대신 서로 다른 학습 변환으로 여러 어텐션을 계산한다. 이것이 **멀티 헤드 어텐션(multi-head attention)**이다.

![어텐션과 Transformer 구조 - 14장 — 12번 그림](/images/ai-study/85c3bed29ab0c6825bdb.png)

왼쪽은 헤드 하나의 계산이다. 아래에서 Q와 K를 곱하고 크기를 조정하며, 필요하면 마스크를 적용하고 Softmax를 거쳐 V를 섞는다. 오른쪽은 이런 계산을 여러 헤드에서 병렬로 한 뒤 결과를 합치는 구조다.

헤드가 8개이고 d\_model이 512라면 각 헤드의 Q·K·V를 64차원으로 만들 수 있다. 세 토큰의 입력 X는 3 × 512, 각 헤드의 W\_Q는 512 × 64, Q는 3 × 64가 된다. **원래 512개 성분을 단순히 앞의 64개, 다음 64개로 잘라 배분하는 개념만은 아니다.** 각 헤드는 전체 입력을 자기 가중치로 64차원에 선형 변환한다. 구현에서는 큰 행렬곱을 한 번 하고 헤드 축으로 나눌 수도 있다.

각 헤드의 결과가 3 × 64이면 여덟 결과를 성분 방향으로 이어 붙여 3 × 512로 만든다. 이를 Concat이라고 한다. 그 뒤 학습 가능한 출력 변환 W\_O를 곱해 여러 헤드의 정보를 다시 섞는다.

![어텐션과 Transformer 구조 - 14장 — 13번 그림](/images/ai-study/5e638669d4fcb2d85d32.png)

![어텐션과 Transformer 구조 - 14장 — 14번 그림](/images/ai-study/6b0c12bd8e2ecf4c9281.png)

“여러 전문가가 같은 문장을 본다”는 비유는 서로 다른 관계를 배울 수 있다는 뜻이다. 1번 헤드는 반드시 주어, 2번 헤드는 반드시 명사라는 역할을 사람이 지정하는 것은 아니다. 헤드의 해석이 항상 명확하거나 서로 완전히 달라야 한다는 보장도 없다. 같은 입력에서 계산을 각각 할 수 있으므로 헤드 내부 계산은 병렬화하기 좋다.

## 12. 순서를 모르면서 문장을 어떻게 이해할까

RNN은 첫 토큰부터 차례로 상태를 갱신하므로 처리 구조에 순서가 들어 있다. 기본 Self-Attention은 토큰 사이의 내용 관계를 계산하지만, 별도 위치 정보가 없으면 “첫 번째”, “세 번째”라는 순서를 같은 방식으로 활용할 수 없다. 토큰을 순서만 바꿔 넣으면 출력 위치도 그에 맞게 바뀌는 성질이 있다.

그래서 입력 임베딩에 **위치 인코딩(positional encoding)**을 더한다. 각 위치를 숫자 패턴으로 표현한 P를 만들어 X+P를 입력으로 사용하는 것이다. 덧셈을 하므로 P의 모양은 X와 같아야 한다. 어휘의 의미 단서에 위치 단서를 겹쳐 준다고 생각하면 된다.

![어텐션과 Transformer 구조 - 14장 — 15번 그림](/images/ai-study/38bd8fd351ed2773f610.png)

원래 Transformer는 여러 주파수의 sin과 cos를 사용하는 위치 인코딩을 제시했다. sin과 cos는 입력에 따라 반복적으로 진동하는 함수다. 성분마다 진동 속도를 달리해 위치별로 다른 패턴을 만든다.

![어텐션과 Transformer 구조 - 14장 — 16번 그림](/images/ai-study/c7ef7b79d5e2e15972f5.png)

pos는 0부터 시작하는 위치이고, 2i와 2i+1은 짝수·홀수 성분 번호다. d\_model은 전체 표현 크기다. 첫 성분 쌍은 빠르게 변하고 뒤쪽 성분 쌍은 더 느리게 변한다. 위치마다 새로운 학습 매개변수를 꼭 만들지 않고도 위치 패턴을 만들 수 있는 방식이다. 학습 가능한 위치 임베딩 등 다른 설계도 있으므로 이 식이 모든 Transformer의 유일한 위치 처리 방식은 아니다.

## 13. “I like movies”에 위치 정보를 직접 더해 보기

표현 크기를 4로 두면 분모는 첫 성분 쌍에서 1, 두 번째 성분 쌍에서 100이다. 따라서 위치 0, 1, 2의 P는 다음과 같다.

![어텐션과 Transformer 구조 - 14장 — 17번 그림](/images/ai-study/e4aa219cd2477207cc8f.png)

위치 0에서도 P는 0 벡터가 아니라 (0, 1, 0, 1)이다. sin(0)=0이고 cos(0)=1이기 때문이다. 그래서 X의 첫 행 (2, 3, 1, 5)에 더하면 (2, 4, 1, 6)이 된다. 이 부분을 빠뜨리면 위치 인코딩의 덧셈을 잘못 이해하게 된다.

이 수치 예제는 덧셈 자체를 보기 위한 것이다. 원래 Transformer에서는 토큰 임베딩을 √d\_model만큼 스케일링한 뒤 위치 정보를 더하는 설정도 포함한다. 그 경우 X를 그 스케일링까지 마친 입력으로 읽으면 된다.

위치 인코딩을 더한다고 기존 토큰의 의미가 사라지는 것은 아니다. 뒤의 가중치들이 의미와 위치가 함께 들어 있는 표현을 바탕으로 관계를 학습한다. 같은 토큰도 위치가 다르면 처음부터 다른 입력 표현을 가질 수 있다.

## 14. 정보를 섞은 다음에는 각 위치의 표현을 바꾼다

어텐션이 다른 위치의 정보를 가져오는 역할이라면, **피드포워드 네트워크(FFN)**는 각 위치에 모인 정보를 새 특징으로 변형하는 역할이다. 원래 Transformer의 FFN은 Dense, ReLU, Dense의 구조이다.

![어텐션과 Transformer 구조 - 14장 — 18번 그림](/images/ai-study/949704d4473b832e7885.png)

첫 선형층이 성분들을 가중합하고, ReLU가 비선형 변형을 넣고, 두 번째 선형층이 다시 d\_model 크기로 돌려놓는다. 원형의 대표 설정에서는 512차원을 2,048차원으로 넓혔다가 512차원으로 줄인다. 8장에서 활성화 함수 없이 선형층만 쌓으면 하나의 선형 변환으로 합쳐질 수 있다고 했던 이유가 여기서도 중요하다.

같은 FFN 가중치를 모든 토큰 위치에 적용한다. 각 위치를 독립적으로 처리한다는 것은 **FFN 자체가 토큰 위치들을 서로 섞지 않는다**는 뜻이다. 이미 어텐션 출력에는 다른 위치의 정보가 들어 있으므로 문맥을 모르는 계산이라는 뜻은 아니다. 서로 다른 인코더 층들은 일반적으로 서로 다른 FFN 매개변수를 가진다.

## 15. Add와 Norm은 이미 배운 계산을 깊게 쌓기 위한 장치다

![어텐션과 Transformer 구조 - 14장 — 19번 그림](/images/ai-study/7475712499c4d7591f8c.png)

붉은 선은 입력을 옆길로 그대로 보내 층의 출력에 더하는 **잔차 연결(residual connection)**이다. skip connection 또는 shortcut이라고도 부른다. 하위 계산 결과를 F(X)라 하면 X+F(X)를 만든다. 두 배열을 더하려면 모양이 같아야 하므로 어텐션과 FFN이 다시 d\_model 크기로 나오는 이유도 보인다.

10장에서 덧셈의 미분은 각 입력에 대해 1이었다. 이 우회 경로 덕분에 정보와 기울기가 여러 변환만을 연속으로 통과하지 않고 전달될 수 있다. 모델이 원래 표현을 유지하면서 필요한 수정량을 더하는 식으로 학습하기 쉬워진다. 그렇다고 전체 네트워크의 기울기 문제가 자동으로 사라지는 것은 아니다.

**Layer Normalization**은 각 토큰 벡터의 성분들을 기준으로 평균과 분산을 계산해 값의 규모를 조정하고, 학습 가능한 확대·축소와 이동 값을 적용한다. 배치 안의 서로 다른 문장들을 한꺼번에 평균 내는 Batch Normalization과 구분해야 한다. 입출력의 급격한 규모 변화가 학습을 어렵게 만드는 문제를 완화하는 데 쓰인다.

![어텐션과 Transformer 구조 - 14장 — 20번 그림](/images/ai-study/5835fd4edbb9338371d4.png)

μ와 σ²는 한 위치의 특징 성분들에서 계산한 평균과 분산이다. ε는 0으로 나누는 것을 막는 작은 양수이며, γ와 β는 학습되는 성분별 조정값이다. 정규화 때문에 신호의 표현력을 무조건 고정해 버리는 것이 아니라, 조정값도 함께 학습한다.

이 장의 그림은 원형의 post-norm 구조인 LayerNorm(X+F(X))를 기준으로 읽는다. 현대 구현에서는 Norm을 먼저 적용하는 pre-norm 등 변형도 있다. Add와 Norm은 같은 연산이 아니라, 우회해서 더하는 연산과 값의 규모를 조정하는 연산 두 개다.

## 16. 여기까지 연결하면 인코더 한 층이 완성된다

![어텐션과 Transformer 구조 - 14장 — 21번 그림](/images/ai-study/84b7432bcdd542f980ca.png)

토큰 임베딩에 위치 정보를 더한 입력이 멀티 헤드 Self-Attention으로 들어간다. 다른 위치의 정보를 모아 새 표현을 만든 뒤 원래 입력을 더하고 LayerNorm을 한다. 다음으로 위치별 FFN을 통과시키고 다시 잔차 연결과 LayerNorm을 적용한다. 이 블록을 여러 층 쌓는다.

입력 토큰이 n개이고 표현 크기가 d\_model이면 마지막 인코더 출력 R도 보통 n × d\_model이다. **문장 전체가 벡터 하나로만 압축되는 것이 아니라, 각 입력 위치의 표현이 남는다.** 이것이 단순 RNN 인코더-디코더의 마지막 상태 하나와 비교할 때 중요한 차이다.

인코더를 깊게 쌓으면 뒤층은 앞층에서 이미 문맥을 반영한 표현을 다시 섞고 변형한다. 이때 “표현을 학습한다”는 말은 학습 과정에서 가중치가 조정된다는 뜻이다. 이미 학습된 모델로 새 문장의 표현을 계산할 때마다 가중치를 다시 학습하는 것은 아니다.

## 17. 디코더는 지금까지 만든 문장과 원문을 함께 본다

![어텐션과 Transformer 구조 - 14장 — 22번 그림](/images/ai-study/e5341a357a7c1587d14f.png)

영어 “I like movies”를 프랑스어 “J'aime les films”로 번역한다고 하자. 인코더는 영어 토큰들의 표현 R을 만들고, 디코더는 이 R과 지금까지의 프랑스어 입력을 사용한다. 디코더에 인코더 출력만 들어가는 것이 아니라 **현재까지 알려진 출력 쪽 토큰**도 들어간다.

| 3 | &lt;sos&gt; J'aime les | films |
| 4 | &lt;sos&gt; J'aime les films | &lt;eos&gt; |

&lt;sos&gt;는 시작, &lt;eos&gt;는 끝을 나타내는 특수 토큰의 설명용 표기다. 모델마다 실제 특수 토큰 이름과 토큰 분할은 다르다. 매 단계 전체 문장을 새로 발명하는 것이 아니라 다음 토큰의 분포를 구하고 선택한 토큰을 뒤에 붙인다. 그러므로 “J'aime les를 반환한다”는 설명은 누적된 결과가 그렇게 된다는 뜻이다.

## 18. 디코더에는 어텐션이 두 종류 들어 있다

![어텐션과 Transformer 구조 - 14장 — 24번 그림](/images/ai-study/d1709f8f1c93411b7222.png)

첫째는 **마스크된 Self-Attention**이다. 출력 쪽 문장에서 현재 위치까지의 토큰끼리 정보를 주고받는다. 둘째는 **Cross-Attention**, 즉 인코더-디코더 어텐션이다. 현재 출력 표현이 원문 인코더의 표현에서 필요한 정보를 가져온다. 마지막 FFN은 그 결과를 각 위치에서 변형한다. 각 하위 층에는 잔차 연결과 정규화가 붙는다.

| 계산 | Q의 출처 | K·V의 출처 | 참고 범위 |
| --- | --- | --- | --- |
| 인코더 Self-Attention | 입력 문장 표현 | 같은 입력 문장 표현 | 패딩 등을 제외한 입력 위치 |
| 디코더 Masked Self-Attention | 출력 쪽 현재 표현 | 같은 출력 쪽 표현 | 현재와 과거 위치 |
| 인코더-디코더 Cross-Attention | 디코더의 표현 | 인코더 최종 출력 | 허용된 원문 위치 |

이 표는 구조를 다시 그릴 때 가장 중요한 구분이다. 어텐션 공식은 비슷하지만 Q·K·V를 어디서 가져오고 어떤 위치를 가리느냐가 역할을 바꾼다.

## 19. 미래를 가리는 이유는 학습할 때 정답을 훔쳐보지 않게 하기 위해서다

“I am” 뒤의 단어를 예측하면서 “a student”를 미리 볼 수 있다면 학습 문제가 지나치게 쉬워진다. 실제 생성 때에는 미래 토큰이 없으므로, 학습할 때에도 해당 위치보다 오른쪽 토큰은 참고할 수 없게 해야 한다. 이것을 **인과적 마스크(causal mask)**라고 한다.

![어텐션과 Transformer 구조 - 14장 — 25번 그림](/images/ai-study/bec67e70979e6f453ec2.png)

![어텐션과 Transformer 구조 - 14장 — 26번 그림](/images/ai-study/d13d8aeac7dc60502b8f.png)

행이 현재 참고 주체이고 열이 참고할 위치라면, 대각선 오른쪽 위가 미래 위치다. 그 위치의 점수를 −∞로 바꾼 뒤 Softmax를 적용한다. exp(−∞)=0이므로 그 위치의 어텐션 비율이 0이 된다. **Softmax를 한 뒤 임의로 값을 지우는 것이 아니라, 점수 단계에서 막은 뒤 정규화**하는 구조다.

![어텐션과 Transformer 구조 - 14장 — 27번 그림](/images/ai-study/b48e0dd1b329b904b433.png)

대각선은 허용된다. 학습 입력이 정답보다 한 칸 뒤로 밀린 형태, 즉 “이전 토큰까지”를 담기 때문이다. 현재 입력 위치의 토큰을 보는 것이 곧 그 위치에서 맞혀야 할 다음 토큰을 보는 것은 아니다. 패딩 마스크는 실제 데이터가 아닌 채움 토큰을 무시하는 용도이므로, 미래를 가리는 causal mask와 목적이 다르다.

![어텐션과 Transformer 구조 - 14장 — 28번 그림](/images/ai-study/abb1b0e4937ba76378c9.png)

마스크 처리 외의 내적·스케일링·Softmax·V 가중합은 앞서와 같다. 헤드가 여러 개이면 각 헤드 결과를 연결하고 W\_O를 적용한다. 도식 위쪽의 Concat은 여러 헤드를 합치는 단계로 읽으면 된다. 단일 scaled dot-product attention의 출력 자체에 반드시 헤드 연결이 필요한 것은 아니다.

## 20. Cross-Attention은 번역할 원문의 어느 부분을 볼지 정한다

마스크된 Self-Attention 뒤의 디코더 표현을 M, 인코더의 최종 표현을 R이라고 하자. Cross-Attention은 M에서 Q를 만들고, R에서 K와 V를 만든다. 디코더가 “지금 만들 출력에 무엇이 필요한가”를 묻고, 원문의 각 위치가 그 질문에 얼마나 관련 있는지 비교하는 셈이다.

![어텐션과 Transformer 구조 - 14장 — 29번 그림](/images/ai-study/c81b23f1f5d7781aebf9.png)

원문 토큰 수가 n이고 출력 쪽 현재 토큰 수가 m이면 점수 행렬은 m × n이다. Self-Attention처럼 항상 정사각형일 필요가 없다. 각 출력 위치가 원문 n개 위치에서 정보를 모으기 때문이다.

인코더가 이미 전체 원문을 읽을 수 있는 번역 설정에서는 출력 쪽의 causal mask를 원문에 그대로 적용하지 않는다. 원문과 출력은 서로 다른 시퀀스다. 다만 원문의 패딩 위치 등은 가릴 수 있다. 각 헤드에서 계산한 뒤 Concat과 W\_O로 합치는 과정은 같은 원리다.

## 21. 마지막 벡터를 어떻게 실제 단어로 바꾸는가

![어텐션과 Transformer 구조 - 14장 — 30번 그림](/images/ai-study/4534469e9c0525bb6cd2.png)

디코더의 최종 벡터는 아직 단어가 아니다. 선형층이 이 벡터를 **어휘 수만큼의 점수**로 바꾼다. 이 정규화 전 점수를 logit이라고 한다. 어휘가 V개이고 표현이 d\_model개 성분이면 출력 가중치의 모양은 보통 d\_model × V이다. 그 다음 Softmax가 각 토큰의 확률을 만든다.

여기서 어텐션의 Softmax와 마지막 Softmax를 구분해야 한다. 어텐션은 “어느 입력 위치를 참고할까”에 대한 비율이고, 마지막은 “어느 토큰을 다음에 낼까”에 대한 확률이다. 같은 함수지만 대상으로 삼는 축이 다르다.

어휘가 \[J'aime, les, films\] 세 항목뿐이고, “&lt;sos&gt; J'aime les” 뒤의 logit이 \[45, 40, 49\]라고 가정하자.

![어텐션과 Transformer 구조 - 14장 — 31번 그림](/images/ai-study/87a8b2c807a960f9369f.png)

49를 공통으로 빼 \[−4, −9, 0\]을 만든 뒤 지수 함수와 정규화를 적용하면 약 \[0.017984, 0.000121, 0.981895\]이다. les의 확률은 매우 작지만 정확히 0은 아니다. 가장 큰 확률을 고르는 방식이라면 films가 선택된다.

이처럼 최댓값을 고르는 방법을 greedy decoding이라고 한다. 확률에 따라 샘플링하거나 여러 후보 경로를 비교하는 방법도 있다. Softmax 자체가 반드시 가장 큰 토큰을 선택하는 것은 아니다. Softmax는 분포를 만들고, **선택 규칙이 그 분포에서 실제 토큰을 고른다.**

## 22. 전체 디코더를 다시 읽으면 각 상자의 이유가 보인다

![어텐션과 Transformer 구조 - 14장 — 32번 그림](/images/ai-study/546dc3c8b098a484fab3.png)

아래쪽에는 한 칸 밀린 출력 토큰과 위치 정보가 있다. 첫 어텐션은 이전 출력 토큰을 참고하고, 가운데 어텐션은 원문 인코더 출력을 참고하고, FFN은 합쳐진 표현을 바꾼다. 이 블록들을 거친 최종 벡터가 Linear와 Softmax를 지나 다음 토큰의 분포가 된다.

![어텐션과 Transformer 구조 - 14장 — 33번 그림](/images/ai-study/753315d974a54d9b8acc.png)

전체 그림의 양쪽 블록 수가 여러 개인 것은 표현을 여러 번 정제하기 위해서다. 원래 Transformer의 대표 설정은 인코더 6층과 디코더 6층이지만, 모든 모델이 6층으로 고정되는 것은 아니다. 각 층마다 같은 종류의 연산을 쓰되 매개변수는 일반적으로 따로 학습한다.

## 23. 학습에서는 정답을 한 칸 밀어 여러 위치를 함께 계산한다

번역 정답이 “J'aime les films &lt;eos&gt;”이면 디코더 학습 입력은 “&lt;sos&gt; J'aime les films”로 만들 수 있다. 각 입력 위치가 바로 다음 정답 토큰을 예측하게 한다. 이전 토큰으로 실제 정답을 넣어 주는 이 방식은 teacher forcing이라고 한다.

| 디코더 입력 위치의 내용 | 그 위치에서 맞힐 정답 |
| --- | --- |
| &lt;sos&gt; | J'aime |
| J'aime | les |
| les | films |
| films | &lt;eos&gt; |

정답 시퀀스가 이미 있으므로 여러 위치의 예측을 한꺼번에 행렬 연산으로 계산할 수 있다. 다만 causal mask로 각 위치가 미래를 보지 못하게 한다. **학습 시 위치들을 병렬로 계산하는 것과, 생성 시 미래 토큰을 미리 아는 것은 다르다.**

각 위치의 예측 분포를 실제 정답과 비교해 교차 엔트로피 손실을 구한다. 정답 토큰에 준 확률이 p라면 그 위치의 기본 손실은 −log(p)이다. 확률을 높게 줄수록 손실이 작아진다. 패딩 위치는 보통 손실 계산에서도 제외한다.

![어텐션과 Transformer 구조 - 14장 — 34번 그림](/images/ai-study/467f77fea231d86c551e.png)

11장에서 배운 역전파가 출력 가중치에서 FFN, 어텐션 투영 가중치, 임베딩까지 필요한 기울기를 계산한다. Adam 같은 최적화 방법이 그 기울기로 매개변수를 갱신한다. 여러 배치를 처리하고 데이터 전체를 반복해서 학습한다. 이 전체 흐름은 입력 준비, 인코더·디코더 순전파, 손실 계산, 역전파, 최적화의 반복이다.

어텐션 비율도 학습의 영향을 받지만, 매 입력에서 계산되는 값 자체를 영구 저장한 표로 고치는 것은 아니다. 그 비율을 만들어 내는 W\_Q·W\_K 등 매개변수가 손실에 맞게 조정된다. 이 구분이 “무엇이 학습되는가”를 정확히 보는 기준이다.

## 24. 추론에서는 미래 토큰을 모르므로 한 토큰씩 생성한다

학습이 끝난 번역 모델에 “I love you”를 넣었다고 하자. 입력을 토큰화하고 임베딩·위치 정보를 만들며, 인코더가 원문 위치별 표현을 계산한다. 디코더는 시작 토큰에서 시작한다.

| 현재까지의 출력 쪽 입력 | 다음 선택의 예 |
| --- | --- |
| &lt;sos&gt; | Je |
| &lt;sos&gt; Je | t' |
| &lt;sos&gt; Je t' | aime |
| &lt;sos&gt; Je t' aime | &lt;eos&gt; |

이 단어 구분 역시 설명용이다. 실제 토크나이저가 같은 경계로 나눈다는 보장은 없다. 종료 토큰, 최대 길이 등의 종료 조건에 도달하면 생성이 끝난다.

이미 생성한 부분을 효율적으로 재사용하는 KV cache 같은 구현에서는 과거 토큰의 key와 value를 저장해 반복 계산을 줄인다. 이것은 추론 중간값의 재사용이지, 모델을 다시 학습하거나 가중치를 바꾸는 것이 아니다. 전체 프롬프트의 초기 처리나 학습은 병렬화할 부분이 많아도, 일반적인 자기회귀 생성은 다음 토큰이 이전 선택에 의존한다.

## 25. BERT·GPT·T5는 같은 부품을 서로 다른 목적에 사용한다

| 계열 | 주로 사용하는 구조 | 대표적인 학습·사용 방식 |
| --- | --- | --- |
| BERT | 인코더 | 양쪽 문맥을 참고해 가려진 토큰을 복원하고, 표현을 분류·질의응답 등에 활용 |
| GPT | 디코더 기반, 보통 별도 인코더와 cross-attention 없음 | 앞 토큰을 조건으로 다음 토큰을 예측하며 텍스트·코드 생성 |
| T5 | 인코더와 디코더 | 입력 텍스트를 출력 텍스트로 바꾸는 형태로 여러 NLP 작업 통일 |
| ViT | 이미지 패치를 토큰처럼 다루는 Transformer | 이미지를 작은 조각으로 나누어 그 표현들 사이의 관계를 학습 |

NLP는 자연어 처리, 즉 사람이 쓰는 언어를 컴퓨터가 처리하는 분야다. LLM은 대규모 언어 모델이다. Transformer는 아키텍처이고 LLM은 규모와 언어 모델이라는 역할을 가리키므로 같은 단어가 아니다. 이미지에 쓰는 ViT만 보아도 Transformer가 텍스트에만 묶인 구조가 아님을 알 수 있다. [BERT](https://arxiv.org/abs/1810.04805), [T5](https://arxiv.org/abs/1910.10683), [ViT](https://arxiv.org/abs/2010.11929)의 원 연구도 이 구분에 해당한다.

### BERT의 예: 빈칸을 양쪽 문맥으로 채우기

“The cat sat on the \[MASK\].”를 입력하면 \[MASK\] 위치의 표현이 앞뒤 토큰을 참고하고, 어휘 분포에서 mat 같은 후보를 예측할 수 있다. 이를 masked language modeling, 즉 마스크 언어 모델링이라고 한다. 입력의 일부를 가리고 복원한다는 점에서 auto-encoding 방식이라고 부르기도 한다.

이것은 BERT의 사전학습을 이해하는 예다. 실제 감성 분류에서는 문장을 입력하고 분류용 출력층을 쓰고, 추출형 질의응답에서는 답의 시작·끝 위치를 예측하는 등 출력 구조가 달라질 수 있다. 모든 BERT 사용이 반드시 \[MASK\] 채우기인 것은 아니다.

### GPT의 예: 앞의 토큰들로 다음 토큰 만들기

“I love”가 들어오면 다음 토큰으로 you를 선택하고, “I love you”를 조건으로 so, 이어 much를 선택할 수 있다. 자기 출력이 다음 입력의 일부가 되는 방식을 autoregressive, 즉 자기회귀 생성이라고 한다. 생성에 필요한 앞 문맥만 볼 수 있게 causal attention을 사용한다.

GPT에 프롬프트를 넣는다고 원형 번역 Transformer의 왼쪽 인코더를 반드시 거치는 것은 아니다. 보통 같은 디코더 기반 토큰 흐름 안에서 프롬프트를 처리하고 이어서 생성한다. 이 차이를 알면 “모든 Transformer에 인코더와 디코더가 둘 다 있나?”라는 혼동을 피할 수 있다.

| 시기 | 변화 | 이 장에서 기억할 의미 |
| --- | --- | --- |
| 1980년대, 1986년의 역전파 연구 확산 | 연결주의와 순환 계산 연구 발전 | RNN의 기원을 한 해로 단정하기보다 시간 의존 정보를 다루는 흐름으로 봄 |
| 1997 | LSTM | 긴 상태 전달에서 정보를 남기고 지우는 통로 도입 |
| 2013 | Word2vec | 단어를 학습된 벡터로 표현하는 방법의 확산 |
| 2014 | Seq2Seq, GRU | 시퀀스를 다른 시퀀스로 바꾸는 구조와 게이트 단순화 |
| 2014 공개·2015 발표 | 어텐션 기반 번역 | 마지막 벡터 하나에 의존하지 않고 원문의 필요한 부분 참조 |
| 2017 | Transformer | 순환 없이 어텐션 중심으로 시퀀스 처리 |
| 2018 | GPT-1, BERT | 생성 중심·양방향 표현 중심의 사전학습 발전 |
| 2019 | GPT-2, T5 | 생성 규모 확대와 텍스트 입출력 작업 통일 |
| 2020 | GPT-3, ViT | 1,750억 매개변수 언어 모델과 이미지 Transformer |
| 2022 | GPT-3.5 계열과 ChatGPT 공개 | 대화형 언어 모델의 대중적 사용 확대 |
| 2023 | GPT-4 | 대규모 언어 모델 활용의 확장 |

GRU의 초기 제안은 [2014년 연구](https://arxiv.org/abs/1406.1078)로 확인할 수 있다. [GPT-3 연구](https://arxiv.org/abs/2005.14165)는 1,750억 매개변수를 보고했고, [ChatGPT 공개 글](https://openai.com/index/chatgpt/)은 2022년 11월 GPT-3.5 계열을 기반으로 했음을 설명한다. 연표는 하나가 등장하면 이전 것이 사라졌다는 뜻이 아니다. CNN·RNN·LSTM은 여전히 데이터와 실행 조건에 따라 선택할 수 있다.

## 27. 직접 연결의 장점에는 계산 비용도 따라온다

RNN은 멀리 떨어진 입력의 영향을 여러 시점에 걸쳐 전달한다. 기본 전역 Self-Attention은 한 층에서 허용된 모든 위치의 조합을 직접 계산한다. 이 때문에 장거리 관계를 다루는 경로를 짧게 만들고, 시퀀스가 주어진 학습에서는 위치별 계산을 병렬화하기 쉽다.

하지만 n개 토큰 사이의 점수 행렬은 n × n이다. 기본적인 밀집 어텐션에서는 길이가 두 배가 되면 위치 쌍은 네 배가 된다. “병렬화할 수 있다”와 “언제나 계산량이 적다”는 같은 말이 아니다. 메모리 사용을 줄이는 구현이나 관계를 일부만 계산하는 변형도 있지만, 기본 구조의 비용을 알아야 긴 문맥이 왜 비싼지 이해할 수 있다.

데이터가 커졌다고 무조건 더 정확해지는 것도 아니다. 학습 목표, 품질, 중복, 편향, 모델 크기와 연산 자원이 함께 영향을 준다. CNN이 공간 구조를, RNN이 순서를 강하게 가정했다면 Transformer는 입력 사이의 관계를 유연하게 학습할 여지가 큰 만큼 데이터와 연산 환경의 중요성도 크다.

## 28. 보안에서는 어느 입력이 어느 계산에 영향을 주는가를 본다

지금까지는 문장을 이해하는 구조를 봤다. 보안 관점에서는 **외부에서 바꿀 수 있는 입력이 어느 결과에 영향을 주는지**로 같은 구조를 다시 읽을 수 있다. 아래는 이 아키텍처를 실제 AI 서비스에 연결했을 때의 공격 표면을 이해하기 위한 구분이다.

| 지점 | 바깥에서 달라질 수 있는 것 | 영향과 구분할 점 |
| --- | --- | --- |
| 학습 데이터 | 오염된 문서·라벨·반복 패턴 | 학습되는 가중치에 편향이나 잘못된 행동이 반영될 수 있음 |
| 토큰화·입력 준비 | 표현이 다른 문자열, 긴 입력, 인코딩 차이 | 사람이 비슷하게 읽어도 토큰 구성·길이·모델 반응은 달라질 수 있음 |
| 프롬프트와 검색 문서 | 사용자 지시, 웹 문서, 도구 결과에 섞인 지시문 | 외부 자료가 원래 작업 지시처럼 취급되면 prompt injection 위험 |
| 긴 문맥과 어텐션 계산 | 지나치게 많은 토큰과 반복 요청 | 계산·메모리·비용 부담. 서비스의 길이·사용량 제한과 연결 |
| 출력 뒤 도구 실행 | 모델이 제안한 명령·인자 | 실제 영향은 하네스의 실행 정책·권한·검증에 의해 결정 |

어텐션이 외부 토큰을 참고한다는 사실만으로 곧바로 권한 상승이 일어나는 것은 아니다. 모델 출력이 실제 파일 접근이나 서비스 변경으로 이어지는 실행 경로가 있어야 한다. 여기서 [에이전트 vs 하네스 vs LLM](/post/ai-foundations-02-agent-harness-llm)과 [MCP](/post/ai-concepts-mcp)의 역할 구분이 다시 중요해진다.

예를 들어 요약할 웹 문서 안에 “이전 지시를 무시하고 다른 일을 하라”는 문장이 있어도, 그것은 읽을 자료이지 사용자의 권한 있는 명령이 아니다. 모델이 둘을 혼동하지 않도록 설계하고, 도구 실행부에서도 허용 범위와 인자를 검증해야 한다. [Anthropic의 prompt injection 설명](https://www.anthropic.com/research/prompt-injection-defenses)도 신뢰할 수 없는 외부 콘텐츠가 에이전트의 행동을 바꾸려는 문제를 다룬다.

또한 **미래 토큰을 가리는 causal mask는 보안 권한 검사 장치가 아니다.** 학습·생성의 정보 접근 순서를 맞추는 수학적 장치다. 비밀 문서를 모델 입력에 넣어 놓고 마스크만으로 사용자별 접근 통제가 완성된다고 볼 수 없다. “어디를 많이 봤는가”라는 어텐션 비율 역시 사실의 정확성이나 안전성을 보증하지 않는다.

## 29. 학습 데이터 환경이 모델의 판단을 바꾼다

언어 모델은 텍스트 안에서 다음 토큰이나 가려진 토큰을 정답으로 만들 수 있다. 사람이 모든 문장에 별도의 분류 라벨을 붙이지 않아도 학습 문제를 만들 수 있다는 점이 자기지도 학습의 장점이다. 하지만 정답을 데이터에서 만들 수 있다는 것이 데이터가 항상 참이라는 뜻은 아니다. 잘못된 주장, 편향, 문맥의 불균형도 함께 학습될 수 있다.

보안 로그에 적용한다면 어떤 시스템의 로그를 어떤 기간에 모았는지, 정상과 공격의 비율이 어떤지, 특정 호스트 이름이 우연히 정답을 암시하는지 확인해야 한다. 학습·검증·시험 데이터가 중복되면 새 상황을 잘 판단하는 것처럼 보일 수도 있다. 1장과 2장에서 배운 일반화와 평가 조건은 Transformer에서도 그대로 필요하다.

외부 검색 결과를 프롬프트에 넣는 것은 이번 입력의 정보를 늘리는 일이다. 모델을 추가 학습시키는 것은 가중치를 바꾸는 일이다. 두 방법은 최신 정보를 다루거나 특정 분야에 맞출 때 함께 사용할 수 있지만 작동 위치가 다르다. 이 구분을 알면 “모델이 무엇을 원래 배웠고, 이번에 무엇을 참고했는가”를 따로 생각할 수 있다.

## 30. 프롬프트 하나를 넣었을 때 머릿속에 그릴 전체 흐름

“이 로그에서 공격 징후를 설명해 줘”라고 요청했다고 하자. 앱이 사용자의 지시와 허용된 로그 자료를 모델 입력으로 구성한다. 텍스트가 토큰 ID로 바뀌고, 각 ID가 임베딩 벡터가 된다. 위치 정보가 더해진 뒤 여러 Transformer 블록을 지난다.

각 블록에서 현재 표현으로 Q·K·V를 만들고, 허용된 위치 사이의 점수를 계산해 Softmax 비율로 내용을 섞는다. FFN은 각 위치의 표현을 변형하고, 잔차 연결과 정규화는 깊은 계산을 이어 가게 돕는다. 마지막 위치의 표현에서 어휘 전체의 logit과 확률을 만들고 다음 토큰을 고른다. 새 토큰을 붙인 뒤 이 과정을 이어 간다.

GPT 같은 디코더 기반 모델이라면 별도의 인코더가 반드시 있는 것은 아니다. 번역용 인코더-디코더 모델이라면 원문 인코더 표현과 출력 디코더 표현이 cross-attention에서 만난다. 어느 구조인지에 따라 전체 그림을 골라야 한다.

이 실행 중 달라지는 것은 입력, 중간 표현, Q·K·V, 어텐션 비율과 생성된 토큰이다. 일반적인 추론에서는 이미 학습된 매개변수를 그대로 쓴다. 학습일 때에만 정답과 손실을 계산하고 역전파·최적화로 매개변수를 바꾼다. 모델이 도구 사용을 요청했다면 실제 실행은 하네스와 도구가 맡는다.

| 앞에서 배운 부품 | 여기서 다시 등장한 위치 |
| --- | --- |
| 1장: 데이터, 학습, 일반화 | 대규모 텍스트 학습과 새 문맥에서의 예측 |
| 2장: 다중 분류, 확률, 손실 | 어휘 전체에서 다음 토큰을 고르는 출력과 교차 엔트로피 |
| 3장: 가중합과 예측 함수 | Q·K·V 투영, FFN, 마지막 선형층 |
| 4\~7장: 방법마다 다른 가정과 데이터 조건 | 어떤 구조가 어떤 데이터 관계를 쉽게 배우는지 비교 |
| 8장: 표현 학습과 비선형성 | 임베딩, 깊은 블록, FFN의 활성화 |
| 10장: 계산 그래프와 경로별 미분 | 행렬곱·Softmax·잔차 경로의 기울기 계산 |
| 11장: 역전파와 최적화의 구분 | 모든 학습 매개변수의 기울기 계산과 Adam 갱신 |
| 12장: 공유 가중치와 구조적 가정 | 토큰 위치에 공유되는 투영·FFN, 공간 지역 연결과 전역 참조의 비교 |
| 13장: 상태 전달과 인코더-디코더 | 긴 전달 경로와 압축 병목을 직접 참조로 완화 |

어텐션은 필요한 위치의 정보를 가중합하는 부품이고, Transformer는 이 부품을 위치 정보·FFN·잔차 연결·정규화·출력층과 조합한 아키텍처다. 다음에 새로운 모델 이름을 만나면, 인코더·디코더 중 무엇을 쓰는지, 어떤 위치를 참고할 수 있는지, 무엇을 예측하도록 학습했는지부터 확인하면 이 지도 위에 놓을 수 있다.
