AI의 계보 페이지를 봤다면 결국 현재 Transformer 모델에 도달했다는 것을 봤을 것이다. Transformer 위에서 대규모 텍스트로 학습한 언어 모델, 즉 LLM(Large Language model)이 나왔고(우리가 흔히 AI라고 부르는 것이다), Anthropic과 OpenAI 같은 회사들이 이 모델을 앞세워 이렇게 말하기 시작했다.

“우리가 만든 모델은 네가 무엇을 물어보든 사람처럼 답하고, 그 답의 정확도와 완성도가 매우 높다.” Anthropic은 이 모델에 Claude라는 이름을 붙이고 Opus, Sonnet, Haiku 같은 계열로 나눠 내놓았고, OpenAI는 GPT 계열 모델을 내놓았다.

그런데 이 모델이 우리의 질문에 대답하려면 그만한 연산이 필요하다. 여기서는 회사 서버의 모델을 API로 사용하는 경우를 보자. 우리는 회사가 정해 둔 규격(API)에 맞춰 텍스트를 보내고 답을 받는다. 모델을 내 컴퓨터에서 실행하는 경우도 있지만, 지금은 원격 모델을 예로 들겠다. 모델은 텍스트를 토큰이라는 작은 처리 단위로 나누어 읽고 만든다. 토큰은 단어 하나일 수도 있고 단어의 일부일 수도 있다. 회사는 이 입력·출력 토큰 수를 요금과 길이 제한을 계산할 때도 쓴다. 일반적인 텍스트 API에서는 우리가 문장을 그대로 보내면 서비스가 토큰으로 바꾸므로, 사용자가 직접 토큰 번호로 변환할 필요는 없다.

문제는 API만으로는 모델을 쓰기가 불편하다는 점이다. 대화를 이어 가려면 이전 대화 중 필요한 내용을 모델이 다시 참고할 수 있게 해야 한다. 앱이 기록을 보내는 방식도 있고, 서버에 저장한 대화나 이전 응답을 ID로 이어 쓰는 방식도 있다. 기록이 길어지면 처리량과 비용이 늘 수 있어 요약하거나 필요한 부분만 남기기도 한다. 그렇다고 무조건 세션을 자주 초기화하는 것이 좋은 것은 아니다. 초기화하면 작업에 필요한 맥락도 사라질 수 있다. 또 모델은 “이 파일을 열어 봐야겠다”고 요청할 수는 있어도, 그 요청만으로 파일이 열리지는 않는다. 실제로 파일을 읽는 도구와 실행 환경, 접근 권한이 있어야 한다. 모델이 원격 서버에 있어서만 생기는 제약은 아니다. 내 컴퓨터의 모델도 연결된 도구가 없으면 파일을 읽지 못한다. 그래서 회사들은 모델을 감싸서 실제 일을 할 수 있게 해 주는 프로그램을 만들었다. Anthropic의 Claude Code와 OpenAI의 Codex 같은 앱이 그 예다. 이런 실행 틀을 하네스라고 부른다.

하네스를 “LLM을 쉽게 쓰게 해주는 것 전부”로 이해하기 쉽지만, 그 핵심은 조금 더 구체적이다. 하네스는 모델을 반복해서 호출하면서 도구를 쥐여 주고, 모델이 요청한 행동을 실제로 실행한 뒤 그 결과를 다시 모델에게 돌려주는 실행 틀이다. 이 하네스 안에 지침(프롬프트)을 넣고, 외부 서비스를 연결하고, 동작 방식을 조절하는 일이 하네스 엔지니어링이다. 그리고 하네스 덕분에 모델이 목표를 향해 스스로 다음 행동을 정하며 일을 끝내게 되면, 그것을 AI 에이전트라고 부른다.

그래서 “AI와 하네스는 무엇이 다른가?”라고 물으면, AI는 지능적인 일을 하는 기술과 시스템을 넓게 부르는 말이고, 하네스는 그 시스템 안에서 모델을 실제 작업에 쓰도록 움직이는 실행 틀이라고 보면 된다. LLM은 판단과 생성을 맡는 모델이고, 에이전트는 모델과 실행 틀이 함께 목표를 향해 다음 행동을 정하며 일하는 시스템이다. 서로 같은 층에 놓인 경쟁 개념이 아니다.

처음 이 개념들을 접할 때 헷갈리기 쉬운 부분은 아래와 같다.

- 토큰 : 모델이 텍스트를 읽고 만드는 처리 단위다. 요금과 길이 제한도 이 단위를 이용한다. 일반적인 텍스트 API에서는 서비스가 변환하므로 사용자가 직접 토큰 번호를 만들 필요는 없다.
- 하네스 : “쉽게 쓰게 해 주는 것 전부”가 아니라 모델에게 도구를 주고 실행 결과를 되먹이며 반복시키는 실행 틀이다.
- MCP : 에이전트를 짜는 도구가 아니라, 외부 서비스를 하네스에 꽂는 공통 규격이다.
- 에이전트 : “정해진 시간에 알림을 보내는 것”은 자동화(언제 시작할지)에 가깝다. 에이전트의 핵심은 판단(무엇을 할지)을 모델이 스스로 한다는 것에 있다.



전체 구조를 그림 한 장으로 보면 아래와 같다. 이 그림은 내 컴퓨터의 하네스가 회사 서버의 모델을 부르는 배치 예다. 하네스도 서버에서 돌 수 있고, 모델도 내 컴퓨터에서 돌 수 있다. 위치가 바뀌어도 역할은 같다. 모델은 다음 행동을 요청하고, 하네스는 권한과 실행 조건을 확인한 뒤 로컬 도구나 원격 서비스에 실행을 맡긴다.

## 1. 모델(LLM) – 뇌
계보의 끝에서 나온 Transformer 기반 언어 모델이다. 텍스트를 받으면 그다음에 올 텍스트를 만들어 낸다. 모든 것의 중심이지만, 혼자서는 할 수 있는 일이 생각보다 적다.

- 할 수 있는 것 : 질문에 답하고, 글을 쓰고, 코드를 짠다.

- 혼자서는 하지 못하는 것 : 현재 입력이나 서비스가 제공한 대화 상태에 없는 과거 대화를 저절로 기억하지는 못한다. 도구 호출 요청을 만들 수는 있지만, 파일 읽기나 명령 실행은 연결된 도구와 실행 환경이 맡는다. API 서비스가 대화를 저장해 이어 주는 기능과 모델 자체의 역할을 구분해야 한다.

- 예 : Anthropic의 Claude(Opus, Sonnet, Haiku), OpenAI의 GPT 계열

---

## 2. API – 뇌에 말을 거는 창구
회사는 모델을 자기 서버에 두고, 인터넷으로 요청을 받는 창구(엔드포인트)를 연다. 우리는 이 창구에 정해진 형식(JSON)으로 텍스트를 보내고, 같은 형식으로 답을 받는다.

```txt
요청: POST https://api.anthropic.com/v1/messages
{ "model": "claude-...", "max_tokens": 1024,
  "messages": [ { "role": "user", "content": "이 로그에 이상한 점이 있어?" } ] }

응답:
{ "content": [ { "type": "text", "text": "3번째 줄에서 ..." } ],
  "usage": { "input_tokens": 25, "output_tokens": 180 } }
```

- 요금 : 응답의 `usage`에 찍힌 입력/출력 토큰 수로 계산한다.
- 불편한 점 : 대화 맥락을 이어 주는 관리가 필요하다. 기록을 직접 보내거나 서버에 저장된 상태를 참조하는 방법이 있으며, 반드시 이전 대화 전체를 직접 다시 보내야 하는 것은 아니다. 모델이 "이 파일을 열어 봐야 한다"고 요청해도, 실제로 여는 일은 도구 실행부가 맡아야 한다.

---

## 3. 하네스 – 뇌에 손발을 달아 주는 실행 틀
하네스(harness)는 원래 말에 채우는 마구(馬具)를 뜻한다. 말의 힘을 실제 일에 쓸 수 있게 묶어 주는 장치다. AI에서는 모델의 능력을 실제 작업에 쓸 수 있게 감싸는 프로그램을 말하며, 아래 과정을 반복한다.

1. 사용자의 요청, 시스템 프롬프트(기본 지침), 쓸 수 있는 도구 목록을 모델에게 보낸다.
2. 모델이 "이 파일을 읽어 줘" 같은 도구 호출을 정해진 형식으로 요청한다.
3. 하네스가 권한과 실행 조건을 확인하고, 도구 실행부에 실제 실행을 맡긴다.
4. 실행 결과를 다시 모델에게 보낸다.
5. 필요한 동안 2\~4를 반복한다. 최종 답변이 나오거나, 사용자가 중단하거나, 실행 한도에 도달하면 멈춘다.

- 그 밖에 하는 일 : 대화 기록 관리, 길어진 대화 요약, 위험한 명령 실행 전 사용자 확인
- 예 : Claude Code(Anthropic), Codex(OpenAI). 넓게 보면 claude.ai나 ChatGPT 같은 채팅 앱도 하네스의 한 형태다.

---

## 4. 도구와 MCP – 손발을 꽂는 규격
하네스가 모델에게 줄 수 있는 도구는 파일 읽기, 명령 실행, 웹 검색 같은 기본 도구만이 아니다. 노션이나 슬랙 같은 외부 서비스도 도구로 붙일 수 있다. 다만 서비스마다 연결 방식이 다르면 매번 새로 만들어야 하므로, Anthropic이 2024년 11월 공통 규격으로 MCP(Model Context Protocol)를 공개했다.

- 비유 : 기기마다 충전 단자가 달랐던 것을 USB-C 하나로 통일한 것과 같다.
- 예 : Claude Code에 Notion MCP를 연결하면, "이 페이지 읽어 줘"라는 요청을 보고 모델이 도구 호출을 요청한다. 하네스가 MCP 서버로 요청을 보내면, 서버가 인증된 계정에 허용된 페이지를 읽어 결과를 돌려준다.

---

## 5. 하네스 엔지니어링 – 하네스를 내 일에 맞게 조정하는 일
같은 모델이라도 하네스를 어떻게 꾸미느냐에 따라 결과가 크게 달라진다. 이를 설계하고 조정하는 일이 하네스 엔지니어링이다.

- 지침 : 시스템 프롬프트, CLAUDE.md 같은 규칙 파일. 프롬프트 엔지니어링은 여기에 속하는 일부다.
- 도구 : 어떤 도구와 MCP를 줄지, 어떤 것은 막을지 정한다.
- 자동 동작 : 특정 시점에 자동 실행되는 훅(hook), 기억을 저장하고 불러오는 방식
- 작업 분담 : 큰 일을 작은 에이전트(서브에이전트)들에게 나눠 맡기는 구조

---

## 6. 에이전트 – 스스로 판단하며 일을 끝내는 것
하네스의 반복 구조 덕분에, 모델은 한 번 답하고 끝나는 것이 아니라 목표를 향해 스스로 여러 단계를 밟을 수 있다. 이것이 AI 에이전트다.

- 예 : "이 서버 로그에서 공격 흔적을 찾아 보고서로 정리해 줘"라고 하면, 에이전트는 로그 파일을 찾고, 읽고, 분석 스크립트를 짜서 실행하고, 결과가 이상하면 다른 방법을 시도한 뒤 보고서를 쓴다. 각 단계에서 무엇을 할지는 사람이 아니라 모델이 정한다.
- 워크플로와의 차이 : 사람이 “1번 다음 2번, 그다음 3번”처럼 순서를 코드로 미리 정해 두면 워크플로다. 모델이 그때그때 다음 행동을 스스로 정하면 에이전트다. Anthropic의 글 “Building Effective Agents”(2024년 12월)가 이렇게 구분한다.
- 자동화와의 차이 : "매일 9시에 실행"은 언제 시작할지를 정하는 것이고, 에이전트의 자율성은 시작한 뒤 무엇을 할지를 스스로 정하는 데 있다.

**정리**

| 구성 요소 | 비유 | 하는 일 | 예 |
| --- | --- | --- | --- |
| 모델(LLM) | 뇌 | 텍스트를 받아 텍스트를 만든다 | Claude Opus/Sonnet, GPT 계열 |
| API | 뇌와 통화하는 창구 | 모델에 요청을 보내고 결과를 받는 접점. 과금 정책은 서비스마다 다름 | Anthropic API, OpenAI API |
| 하네스 | 손발이 달린 몸 | 모델을 반복 호출하며 도구를 실행해 준다 | Claude Code, Codex |
| MCP | 손발을 꽂는 콘센트 규격 | 외부 서비스를 같은 방식으로 연결한다 | Notion MCP, Slack MCP |
| 하네스 엔지니어링 | 몸을 일에 맞게 훈련시키는 것 | 지침, 도구, 권한, 자동 동작을 설계한다 | CLAUDE.md, 훅, 서브에이전트 |
| 에이전트 | 스스로 일하는 사람 | 목표를 향해 다음 행동을 스스로 정하고 반복한다 | 로그 분석 후 보고서까지 쓰는 Claude Code |

## LLM을 쉽게 쓰기 위해 도와주지만 하네스가 아닌 것?

하네스는 결국 사람이 LLM을 실제 일에 쓸 수 있게 하려고 존재한다. 다만 “LLM을 쉽게 쓰게 돕는 것”은 여러 층에 걸쳐 있고, 하네스는 그중 한 층이다. 그래서 “쉽게 쓰게 해 주면 하네스다”라고 하면 다른 층까지 하네스에 들어가 버린다.

| 도구 | 하는 일 | 하네스가 아닌 이유 |
| --- | --- | --- |
| **SDK** (예: Anthropic의 Python 라이브러리) | client.messages.create(...) 한 줄로 API를 호출하게 해 준다 | HTTP 요청을 대신 만들어 줄 뿐이다. 모델이 "파일을 읽어 줘"라고 답해도 그걸 실행하고 결과를 되돌려 주는 반복은 개발자가 직접 짜야 한다 |
| **모델 실행 서버** (예: Ollama, vLLM) | 내 컴퓨터나 서버에서 모델을 돌려 준다 | 모델을 "켜 주는" 층이다. 하네스보다 한 층 아래에 있다 |
| **API 중계 서비스** (예: OpenRouter) | 여러 회사의 모델을 하나의 창구로 쓰게 해 준다 | 요청을 받아 해당 회사로 넘겨줄 뿐, 실행이나 반복은 하지 않는다 |
| **토크나이저/토큰 계산기** | 텍스트가 몇 토큰인지 미리 세어 비용을 예측하게 해 준다 | 계산 보조 도구다 |
| **MCP 서버** (예: Notion MCP) | 노션 읽기/쓰기 같은 기능을 도구로 제공한다 | 하네스에 꽂히는 부품이다. 하네스가 있어야 모델이 그 도구를 쓸 수 있다 |
| **벡터 DB** (RAG에 쓰는 검색 저장소) | 관련 문서를 찾아 모델 입력에 넣을 재료를 준다 | 하네스나 앱이 가져다 쓰는 부품이다 |
| **파인튜닝 도구** | 모델 자체를 내 데이터로 추가 학습시킨다 | 하네스는 모델을 감싸는 쪽이고, 파인튜닝은 모델 자체를 바꾸는 쪽이다 |

층으로 보면 아래와 같다.

```txt
[모델 실행]   회사 서버, Ollama, vLLM        ← 모델을 돌린다
[접근 창구]   Anthropic API, OpenRouter       ← 모델에 요청을 보낸다
[호출 도우미] SDK                             ← 요청을 쉽게 만든다
[하네스]      Claude Code, Codex              ← 반복 실행 + 도구 실행
[부품]        MCP 서버, 벡터 DB, 각종 도구    ← 하네스에 꽂혀 쓰인다
```

모든 층이 “LLM을 쉽게 쓰게” 돕는다. 그중 하네스만 하는 일이 있다.

## 하네스인지 가리는 질문

“모델의 출력을 보고 무언가를 실제로 실행한 뒤, 그 결과를 다시 모델에게 돌려주는가?”

- 그렇다 → 하네스 : Claude Code는 모델이 “이 파일 읽어 줘”라고 하면 실제로 읽고, 내용을 다시 모델에게 보낸다.
- 아니다 → 하네스가 아님 : SDK는 요청 한 번 보내고 답 한 번 받으면 끝이다.

하네스라는 말은 범위를 하나로 고정한 표준 정의가 없어 경계가 흐린 경우도 있다.

- **최근 SDK:** 도구 호출 반복을 자동으로 돌려 주는 기능이 붙기도 합니다(예: Anthropic SDK의 tool runner). 그 기능을 쓰는 순간 SDK가 하네스 역할의 일부를 하는 셈입니다.
- **Claude Agent SDK:** Claude Code의 하네스를 라이브러리 형태로 떼어 낸 것이라, 이름은 SDK지만 하네스입니다.
- **번역 버튼 같은 단순 앱:** API를 한 번 호출하고 결과를 보여 주기만 하면 반복도 도구 실행도 없어서, 보통 하네스라고 부르지 않습니다.
