여기서 말하는 분류란 입력을 보고, 미리 정해진 몇 개의 카테고리 중 어디에 속하는지 맞히는 문제이다. 이 카테고리를 클래스라고 부른다.

- 입력 : 데이터 하나의 특징들이다. 예를 들어 패킷 수, 바이트 수, 포트 같은 값이다.
- 정해진 이름표 중 하나이다. 예를 들어 “공격” 또는 “정상”이다.
- 분류기(classifier) : 이 일을 하는 모델이다.
- 핵심은 출력이 “개수가 정해진 선택지”라는 점이다. 답이 3.7이나 85점처럼 연속된 숫자가 아니라, 몇 개의 보기 중 하나를 고르는 객관식 문제이다.

**예시 (위 두 개는 이진 분류, 아래 두 개는 다중 분류)**

| 문제 | 클래스 | 종류 |
| --- | --- | --- |
| 이 메일은 스팸인가? | 스팸 / 정상 | 이진 분류 (클래스 2개) |
| 이 트래픽은 공격인가? | 공격 / 정상 | 이진 분류 |
| 이 손글씨는 무슨 숫자인가? (MNIST) | 0 \~ 9 | 다중 분류 (클래스 10개) |
| 이 악성코드는 어느 패밀리인가? | Emotet / TrickBot / Ryuk … | 다중 분류 |

![분류(Classification) - 2장 — 1번 그림](/images/ai-study/3e9531b9974cff8b1d68.png)

숫자 이미지를 예로 들면 한 샘플은 이미지 한 장이다. MNIST에는 숫자 이미지 70,000장이 있고, 한 장은 28 × 28 픽셀이다. 픽셀을 펼치면 입력 특성 784개가 된다. 정답 숫자 0\~9는 특성 10개가 아니라 출력의 선택지 10개이다. 5-감지기는 이 중 “5인가 아닌가”만 묻도록 정답을 다시 만든 이진 분류 문제이다.

![분류(Classification) - 2장 — 2번 그림](/images/ai-study/93ed3e1832d5fae1f796.png)

같은 모양의 5도 필기체와 굵기가 다르다. 모델은 특정 이미지 하나를 기억하는 대신 새로운 필체에도 같은 범주를 줄 수 있어야 한다. 이 때문에 학습에 쓰지 않은 이미지로 평가해야 한다.

### 기계학습에서 왜 분류가 나오는가?

1장에서 기계학습은 사람이 규칙을 짜지 않는다고 했다. 대신 데이터와 정답을 주면 기계가 규칙(함수)을 만든다. 이때 정답이 어떤 모양이냐에 따라 문제의 종류가 갈린다.

- 정답이 카테고리면 분류이다. 예를 들어 “공격 / 정상”이다.
- 정답이 숫자면 회귀이다. 예를 들어 “위험 점수 73.5”이다.

1장의 지도 학습 부분에 적은 “두 종류 : 분류 / 회귀”가 바로 이것. 2장은 분류를 다루고, 3장은 회귀를 다룬다. 이 두 장은 “지도 학습이 푸는 문제 두 가지”를 하나씩 보는 구성이다.

### 분류는 결국 “경계선을 긋는 일”이다

분류기가 배우는 함수는 특징 공간에 선을 긋는 일과 같다. “한 공간에서 특정 선을 기준으로 이쪽은 공격, 저쪽은 정상”으로 나누는 것이다. 이 선을 결정 경계(decision boundary)라고 부른다. 앞으로 배울 알고리즘은 이 선을 긋는 방법이 서로 다를 뿐이다.

- 4장 KNN : 가장 가까운 이웃이 어느 쪽인지로 정한다.
- 5장 결정트리 : “포트가 445인가?” 같은 질문을 이어 붙여 공간을 네모나게 자른다.
- 6장 SVM : 두 클래스 사이의 여백(마진)이 가장 넓은 선을 긋는다.

### 보안 문제의 대부분이 분류다

보안에서 기계학습으로 푸는 문제를 떠올려 보면 대부분 이 모양이다

- 침입 탐지 : 이 트래픽이 공격인가, 정상인가
- 악성코드 탐지 : 이 파일이 악성인가, 정상인가
- 피싱 탐지 : 이 URL이 피싱인가
- 악성코드 분석 : 이 악성코드는 어느 패밀리인가

“얼마나”보다 “무엇인가 / 맞나 아닌가”를 묻는 경우가 많다.

![분류(Classification) - 2장 — 3번 그림](/images/ai-study/48ce985a355ba2237965.png)

이 공부 트리에 있어서 순서는 2가지 기준이 있다.

- 난이도 순서 : 가장 단순한 모델에서 복잡한 모델로 간다
- 문제와 해결 순서 : 각 장의 모델이 남긴 약점을 다음 장의 모델이 고친다.
- 이 순서는 이해를 위한 구성이다. 실제 연구 역사는 서로 겹치며, 다음 모델이 앞 모델을 모든 문제에서 대체했다는 뜻은 아니다.

| 기준 (무엇을 묻나) | 선택지 | 이 문제의 선택 |
| --- | --- | --- |
| 정답(레이블)이 있나? | 지도 / 비지도 / 준지도 / 강화 학습 | **지도 학습** |
| 데이터가 들어올 때마다 계속 배우나? | 배치 학습 / 온라인 학습 | **배치 학습** |
| 새 데이터를 어떻게 예측하나? | 사례 기반 / 모델 기반 학습 | **모델 기반 학습** |

![분류(Classification) - 2장 — 4번 그림](/images/ai-study/ebe79ab320524f28a015.png)

위와 같이 기계학습 시스템을 나누는 기준은 3개로 볼 수 있다.

1. 학습할 때 정답(레이블)을 보는가?

1. 지도 학습
2. 비지도 학습
3. 준지도 학습
4. 강화 학습

2. 배치한 뒤에도 계속 배우나?

1. 배치 학습
2. 온라인 학습

3. 데이터를 요약해 두나, 그대로 들고 있나?

1. 사례 기반
2. 모델 기반

기준1은 우리가 1장에서 공부를 했기에 2장부터 간단하게 알아보겠다.

### 기준 2 - 배치 후에도 계속 배우는가? (배치 학습 / 온라인 학습)

**이 기준이 왜 필요한가**

모델을 한 번 만들어 서비스에 내보내도 세상은 계속 바뀐다. 새 스팸 수법이 나오고, 새 공격 기법이 나온다. 이때 “모델을 어떻게 새 데이터에 맞춰가나”에는 두 가지 답이 있다.

- **처음부터 다시 만든다.** 이것이 배치 학습.
- **기존 모델을 이어서 고친다.** 이것이 온라인 학습.

기준 2는 이 두 답을 가르는 질문이다.

정리할 단어. (배치 학습의 배치는 batch이다.)

- 배치 (batch) : “묶음”이라는 뜻으로, 데이터를 한 묶음으로 넣는다는 의미다.
- 배치 (deploy) : “실전에 내보낸다”는 뜻이다. 학습이 끝난 모델을 서비스에 올리는 것이다.

### 배치 학습 (Batch Learning)

- 정의 : 가용한 데이터를 모두 사용해 한 번에 학습한다. 학습이 끝난 모델을 배치(deploy)하고, 서비스 중에는 더 배우지 않고 예측만 한다. 학습을 서비스와 떨어진 곳에서 미리 끝내므로 오프라인 학습이라고도 부른다.

- 과정 :

1. 데이터를 모은다.
2. 데이터 전체로 학습한다(fit).
3. 검증 세트와 테스트 세트로 성능을 확인한다.
4. 모델을 서비스에 배치한다.
5. 서비스 중에는 predict만 부른다. 파라미터는 학습이 끝난 순간의 값으로 고정된다.

- 새 데이터를 반영하는 법 : 기존 데이터와 새 데이터를 합쳐서 처음부터 다시 학습한다. 그다음 새 모델로 교체한다.

- 예 : 1월에 작년 메일로 학습해 배치한 스팸 필터는, 3월에 새 수법의 스팸이 쏟아져도 스스로 바뀌지 않는다. ChatGPT나 Claude 같은 LLM도 한 번 학습한 뒤 배치되고, 대화 중에는 가중치가 바뀌지 않는다. 다만 검색·도구·제공된 문맥으로 새 정보를 사용하는 일은 가중치를 새로 학습하는 일과 다르다.

**장점**

- 검증한 그대로 내보낸다 : 테스트 세트로 확인한 바로 그 모델이 서비스에 나간다.
- 통제하기 쉽다 : 데이터 검사를 거친 뒤 모델을 교체할 수 있다. 다만 오프라인 학습도 수집 데이터가 오염되면 영향을 받으므로 방식만으로 안전성이 보장되지는 않는다.
- 재현된다 : 같은 데이터와 같은 설정이면 같은 모델이 나온다. 문제가 생기면 이전 모델로 되돌리기도 쉽다.
- 반복 학습을 설계하기 쉽다 : 저장한 데이터를 섞어 여러 바퀴 학습할 수 있다. 다만 데이터의 편향이 자동으로 사라지거나 성능이 항상 더 좋아지는 것은 아니다.

**단점**

- 재학습 비용 : 데이터가 크면 처음부터 다시 학습하는 데 시간과 계산 자원이 많이 든다.
- 변화에 늦다 : 학습 시점과 지금 사이의 변화를 반영하지 못한다.
- 자원이 부족하면 못 쓴다 : 데이터 전체를 저장하고 처리할 메모리와 저장 공간이 있어야 한다.

실무에서는 그렇기에 주기적 재학습으로 타협한다.\
→ 매일 밤이나 매주처럼 정해진 주기로 새 데이터를 합쳐 다시 학습하고 모델을 교체한다. 재학습이 자동화됐을 뿐, 서비스 중인 모델이 스스로 배우지는 않으므로 여전히 배치 학습이다.

### 온라인 학습 (Online Learning)

- 정의 : 데이터를 하나씩 또는 작은 묶음(미니배치)으로 받을 때마다 기존 모델을 이어서 조금씩 학습시킨다. 처음부터 다시 학습하지 않는다.

- 과정 :

1. 초기 모델을 만든다.
2. 새 데이터 묶음이 오면 그 묶음으로 파라미터를 조금 고친다.
3. 다 쓴 묶음은 버려도 된다.
4. 2\~3을 계속 반복한다. 학습이 “끝나는”시점이 없다.

- sklearn : fit()은 일반적으로 새 학습을 수행한다. 일부 모델의 warm\_start처럼 이전 상태를 재사용하는 예외가 있다. partial\_fit()은 부를 때마다 이어서 학습한다. partial\_fit을 지원하는 모델(예: SGDClassifier)만 온라인 학습이 된다.

학습률 - 온라인 학습의 핵심 손잡이

- 정의 : 새 데이터에 얼마나 빨리 적응할지 정하는 하이퍼 파라미터다.
- 높으면 : 새 데이터에 빨리 적응한다. 대신 예전에 배운 것을 빨리 잊는다.
- 낮으면 : 안정적이고 잡음에 덜 흔들린다. 대신 변화에 둔하다.
- 배치 학습에서 학습률은 “최적점까지 가는 보폭”이다. 온라인 학습에서는 보폭이면서 동시에 “옛것을 얼마나 빨리 잊나”이기도 하다.

**외부 메모리 학습 (out-of-core learning)**

- **정의 :** 데이터가 너무 커서 메모리에 한 번에 못 올릴 때, 데이터를 조각내서 하나씩 읽어 들여 온라인 학습 방식으로 학습한다.
- **의미 :** 이 학습은 서비스 전에 오프라인에서 끝난다. 그래도 방식은 온라인 학습이다. 그래서 "온라인"은 실시간이나 인터넷이라는 뜻이 아니다. "점진적으로(incremental) 이어서 배운다"는 뜻이다.

**장점**

- **빠른 적응 :** 변화가 빠른 데이터에 맞춰 바로바로 바뀐다. 예를 들어 주가, 실시간 트래픽이 있다.
- **자원 절약 :** 다 쓴 데이터를 버릴 수 있어 저장 공간과 메모리가 적게 든다.
- **거대한 데이터 :** 메모리보다 큰 데이터도 학습할 수 있다(외부 메모리 학습).

**단점과 위험**

- **나쁜 데이터에 서서히 망가진다 :** 센서 고장, 잘못된 로그, 조작된 입력이 들어오면 모델이 그대로 배운다. 성능이 천천히 떨어져서 알아채기도 어렵다.
- **대응 :**
  - 성능을 계속 감시하다가 떨어지면 학습을 멈추고 이전 모델로 되돌린다.
  - 입력 데이터를 감시해 비정상 데이터를 걸러낸다. 이 감시에 비지도 학습의 이상 탐지를 쓸 수 있다.
- **검증이 어렵다 :** 모델이 계속 바뀌므로, 어제 측정한 성능이 오늘의 모델에 맞는다는 보장이 없다.
- **순서에 끌려간다 :** 데이터를 섞을 수 없고 도착한 순서대로 배운다. 그래서 최근 데이터 쪽으로 기운다.

위에서는 분류기가 무엇이고, 어떻게 하는지를 대략적으로 알아보았다.

이제는 분류기를 어떻게 채점하는 지를 알아보겠다. 이것이 AI 벤치마크의 핵심이라고도 볼 수 있다.

## 교차 검증과 성능 측정 지표

**왜 공정한 시험이 먼저 필요한가**

학습에 사용한 데이터로 다시 채점하면 새 데이터 성능보다 점수가 높게 나올 수 있다. 그 차이가 크고 새 데이터 성능이 나쁜 현상이 과대적합이다. 모든 모델이 훈련 데이터를 거의 외운다고 가정할 필요는 없다. 교과서 연습 문제를 그대로 시험에 내는 것과 같다.

그렇다고 테스트 세트를 쓸 수는 없다. 테스트 세트는 모든 선택이 끝난 뒤 마지막에 한 번만 쓰는 수능이기 때문이다. 지금은 아직 모델을 고르고 다듬는 중이다.

그래서 훈련 데이터 안에서 시험을 만든다. 이것이 “교차 검증”이다.

1. 훈련 데이터를 여러 조각(예: 3조각)으로 나눈다.
2. 두 조각으로 학습하고, 남은 한 조각으로 시험을 본다.
3. 시험 보는 조각을 바꿔 가며 반복한다.

이렇게 하면 모든 데이터가 한 번씩 “학습에 안 쓰인 시험 문제”가 된다.

교차 검증은 이 단원 전체에서 두 번 쓰인다.

1. 정확도를 공정하게 잴 때\
: 조각마다 맞힌 비율을 계산하고 평균을 낸다.
2. 뒤의 모든 성적표를 만들 때\
: 오차 행렬, 정밀도, 재현율, 그래프를 만들려면 데이터마다 “모델이 처음 보고 내린 판정”이 필요하다. 교차 검증을 돌리면서 각 조각의 판정을 버리지 않고 모아 두면, 훈련 데이터 전체에 대해 공정한 판정이 한 벌 생긴다. 판정 대신 점수를 모아두면, 기준선을 옮기며 그리는 그래프의 재료가 된다.

채점에는 질문이 두 개가 있다.

| 질문 | 담당 |
| --- | --- |
| **어떤 문제로 시험을 보나?** 모델이 학습 때 본 데이터로 채점하면 안 된다 | 교차 검증 |
| **무엇을 기준으로 점수를 매기나?** 맞힌 비율인지, 헛경보인지, 놓친 것인지 | 정확도, 정밀도, 재현율 등 |

- 교차 검증은 첫 번째 질문의 답이다. 공정한 시험을 치르게 해 주는 장치이다.
- 정확도나 정밀도는 두 번째 질문의 답이다. 채점 기준이다.

정확도, 정밀도 라는 개념을 오차 행렬로 공부해보자.

![분류(Classification) - 2장 — 5번 그림](/images/ai-study/4b84b78d910872078288.png)

TN, TP, FN, FP 네 개 모두 데이터 하나를 판정한 결과의 종류이다. 데이터 하나마다 두 가지를 확인하면 반드시 이 넷 중 하나로 들어간다.

- 뒤 글자 = 모델의 판정 : P(Positive)는 “양성이라고 했다”, N(Negative)은 “음성이라고 했다”이다.
- 앞 글자 = 실제 판정이 맞았나 : T(True)는 맞았음, F(False)는 틀렸음.

그래서 이름을 뒤에서부터 읽으면 뜻이 된다. 예를 들어 FP는 “양성이라고 했는데(P), 틀렸다(F)”이다.

여기서 헷갈리면 안 되는 점이 있다.

실제 양성이지만 예측을 음성이라고 했다면? → TN이 아닌 FN이다.

앞쪽 알파벳은 실제로 맞았는지가 아니라 AI의 예측 결과에 대한 말이다.

음성이라고 했는데 실제로 양성이었으면 예측이 틀렸기에 앞쪽 알파벳에 F가 오는 것이다.

그렇다면 여기서 중요한 공식이 2개가 있다.

바로 재현율과 정밀도이다.

- 재현율 : 실제 양성이었던 것 중에 모델에 실제로 잡은 것의 비율은 어떻게 되는가?

→ TP / (FN + TP)가 될 것이다.

- 정밀도 : 모델이 양성이라 예측한 것 중에 실제 양성의 비율

→ TP / (FP + TP)가 될 것이다.

여기서 중요한 핵심은 정밀도와 재현율의 Trade Off는 기준선(임계값)을 옮겨서 한쪽을 올리면 다른 쪽이 내려가는 관계라는 것이다.

- 재현율을 올리려고 기준선을 낮추면 : 더 많은 양성을 잡고 FP도 늘 수 있다. 정밀도는 낮아지는 경우가 많지만 실제 점수 순서에 따라 달라진다.

- 기준선을 높이면 : 양성 판정 수와 재현율이 줄어들 수 있다. 정밀도가 얼마나 좋아지는지는 실제 데이터로 확인한다.

### 정확도 99%가 공격 탐지 성공을 뜻하지 않는 이유

10,000건 중 공격이 100건뿐이면 전부 정상이라고 답해도 정확도는 99%이다. 그러나 공격 100건을 하나도 찾지 못했다. 공격을 양성으로 정하고 다음 탐지기의 결과를 보자.

| 실제 상태 | 공격이라고 예측 | 정상이라고 예측 |
| --- | --- | --- |
| 실제 공격 100건 | TP = 80 | FN = 20 |
| 실제 정상 9,900건 | FP = 180 | TN = 9,720 |

이 탐지기의 정확도는 98%로 항상 정상이라 답하는 기준보다 낮다. 그래도 공격 80건을 찾았다. 정밀도는 80/260으로 약 30.8%, 재현율은 80/100으로 80%이다. 분석가가 받는 경보 중 약 69.2%는 오탐이므로 경보 처리 비용도 함께 고려해야 한다.

![분류(Classification) - 2장 — 6번 그림](/images/ai-study/d6a77646e6c9c54636b1.png)

실제 공격을 많이 찾으려는지, 경보 하나의 신뢰도가 필요한지에 따라 평가 기준이 달라진다. 공격을 양성으로 정의하지 않으면 숫자의 해석도 달라지므로 양성 클래스부터 명확히 정해야 한다. 분모가 0인 지표는 수학적으로 정의되지 않으므로 평가 도구의 처리 규칙도 확인한다.

## F1 score란

정밀도와 재현율을 하나의 숫자로 합친 점수이다. 둘 중 하나라도 낮으면 같이 낮아지도록 만들어져 있다.

왜 필요한가

정밀도와 재현율은 수자가 두 개라서 모델이나 기준선을 비교하기 어렵다.

|  | 정밀도 | 재현율 |
| --- | --- | --- |
| 모델 A | 90% | 60% |
| 모델 B | 70% | 80% |

A는 정밀도가 높고, B는 재현율이 높다. 그래서 어느 쪽이 더 나은지 바로 말할 수 없다. 이럴 때 “둘을 고르게 다 잘하는가”를 숫자 하나로 보려고 F1을 쓴다.

**어떻게 구하나**

F1 = 2 × 정밀도 × 재현율 / (정밀도 + 재현율)

## 점수에서 판정으로: 임계값을 움직여 보기

![분류(Classification) - 2장 — 7번 그림](/images/ai-study/5a93c9b85c88000e8a1a.png)

점수 순으로 정렬된 샘플에 기준선을 놓는다. 기준보다 높은 것을 양성으로 판정하면 기준선을 낮출수록 더 많은 샘플을 잡는다. TP와 FP는 함께 늘 수 있고 재현율은 내려가지 않는다. 반대로 기준선을 높이면 FN이 늘 수 있다. 정밀도는 흔히 반대 방향으로 움직이지만 실제 데이터의 점수 순서에 따라 출렁일 수 있어 엄밀한 단조 관계는 아니다.

![분류(Classification) - 2장 — 8번 그림](/images/ai-study/508a6b7dd1d5fc916895.png)

그림의 가로축은 임계값이고 세로축은 정밀도·재현율이다. 여기에 나타난 양수·음수 점수는 확률이 아니라 분류기의 결정 점수이다. 0.5라는 확률 기준과 수천 단위 점수 기준을 섞어 읽으면 안 된다.

5-감지기 예제에서 TP가 4,096, FP가 1,522, FN이 1,325라면 정밀도는 약 72.9%, 재현율은 약 75.6%, F1은 약 74.2%이다. 이 값은 해당 학습·검증 구성의 결과이며 알고리즘 이름만으로 정해지는 성능이 아니다.

## ROC 곡선과 PR 곡선은 무엇을 다르게 보여 주는가

![분류(Classification) - 2장 — 9번 그림](/images/ai-study/db32885c1178b3fa791a.png)

ROC 곡선의 세로축 TPR은 재현율과 같고, 가로축 FPR은 실제 정상 중 잘못 경보를 낸 비율이다. FPR의 분모는 모든 예측 양성이 아니라 FP + TN이다. 앞의 10,000건 예에서는 FPR이 약 1.82%로 작아도 거짓 경보가 180건이다. 정상 데이터가 매우 많으면 작은 비율도 큰 업무량이 된다.

ROC-AUC는 이 곡선 아래 면적이다. 일반적인 이진 점수 평가에서 임의의 양성을 임의의 음성보다 높은 점수에 놓는 능력으로 해석할 수 있다. 동점은 보통 절반으로 반영한다. 1이면 완전한 순위 분리이고, 무작위 점수의 기대값은 0.5이다. AUC가 높다는 사실만으로 선택한 임계값의 경보가 유용하다고 말할 수는 없다.

PR 곡선은 가로축 재현율, 세로축 정밀도를 사용한다. “얼마나 찾았을 때 그 경보가 얼마나 믿을 만한가”를 보여 주므로 양성이 드문 탐지에서 특히 유용하다. 무작위 순위의 정밀도 기준선은 양성 비율에 영향을 받는다. 따라서 공격 비율이 다른 데이터셋의 PR 값은 조건을 함께 적어 비교한다.

PR 곡선을 숫자로 요약하는 AP와 사다리꼴 방식의 PR-AUC는 같은 계산이 아니다. 1장의 제로샷 사례에서 표현이 비슷해도 순위 지표와 고정 임계값의 F1이 다르게 움직였던 이유가 여기 있다. [scikit-learn 평가 지표 문서](https://scikit-learn.org/stable/modules/model_evaluation.html)

## 정답이 여러 개 중 하나이면: 다중 분류

![분류(Classification) - 2장 — 10번 그림](/images/ai-study/6bfafcf8432bf41d6a86.png)

다중 분류는 정답 하나를 여러 범주에서 고르는 문제이다. OvR은 One-vs-Rest이며 OvA, One-vs-All이라고도 한다. 각 범주와 나머지를 구별하는 모델 K개를 만든다. OvO는 One-vs-One이며 범주 쌍마다 모델을 만들어 K(K − 1)/2개를 사용한다. 10개 숫자라면 각각 10개와 45개이다.

OvO의 모델 수는 많지만 각 모델은 두 범주의 데이터만 학습한다. 어느 방식이 빠른지는 기반 알고리즘과 데이터 크기에 달려 있다. 소프트맥스처럼 모든 범주를 한 모델에서 함께 학습하는 방법도 있으므로 모든 다중 분류가 이진 모델의 묶음인 것은 아니다.

다중 분류의 혼동 행렬은 실제 클래스와 예측 클래스를 각각 행과 열에 놓아 어떤 종류끼리 헷갈리는지 보여 준다. 클래스별 지표를 같은 비중으로 평균하면 macro 평균이고, 클래스별 표본 수를 반영하면 weighted 평균이다. 드문 공격 종류의 실패가 전체 평균에 가려지는지도 확인해야 한다.

여러 태그가 동시에 정답일 수 있는 다중 레이블 문제는 별도이다. 파일 하나에 랜섬웨어 기능과 전파 기능이 모두 있을 수 있다면, 단 하나만 고르는 다중 분류로 억지로 표현하면 정보가 사라진다. 이제 [회귀(Regression) - 3장](/post/ai-foundations-05-regression)에서 점수와 확률이 실제로 어떻게 계산되는지 살펴볼 수 있다.
